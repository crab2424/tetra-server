# tetra-server

`TETLABO` のサーバーサイド実装です．  
オンラインでマルチプレイをやる際の基盤として使用することを想定しています．

# ローカル環境構築

Rustをインストールしている状態で

```bash
$ cargo run
```

で実行できます．

または，フロントエンド実装 `tetra-programming` が同ディレクトリにある状態なら， `tetra-programming` の開発サーバー起動コマンドで同時に起動できます．

# 実装

通信は全てクライアントサーバーモデルで， WebRTC を使用して通信します．  
シグナリングには WebSocket を使用します．

全て C/S モデルのため，クライアント同士の P2P 通信は行われず，サーバーが通信を経由する形になります．

# 接続の許可判定（プロトコル番号）

クライアントの接続許可は，`src/main.rs` の `PROTOCOL_VERSION`（整数の通信プロトコル番号）で判定します．
アプリのバージョン番号（`package.json` の version）とは別物で，シグナリング/ゲームフレームの形式や
相手に影響する対戦ルールを変えたときだけ上げます．見た目の変更やモード単体の修正では上げません．

`ALLOW_VERSIONS` は，`protocol` を送らない旧クライアント（2.2.0以前）向けの移行期間限定の
互換判定にのみ使われます．`protocol` を送る新しいクライアントはこの値を無視します．

# Environment Variables

| KEY                 | 説明                                                                                  | 例               |
| ------------------- | ------------------------------------------------------------------------------------- | ---------------- |
| `HTTP_ADDR`         | HTTPサーバーをホストするアドレスを指定します                                          | `127.0.0.1:8080` |
| `ALLOW_VERSIONS`    | `protocol` を送らない旧クライアント（2.2.0以前）向けの許可バージョン一覧をカンマ区切りで指定します（上記参照） | `2.1.0,2.1.1`    |
| `CF_TURN_TOKEN_ID`  | Cloudflare TURN のトークンIDを指定します (指定されない場合は，TURNは利用されません．) | `xxxx`           |
| `CF_TURN_API_TOKEN` | Cloudflare TURN の APIトークンを指定します                                            | `xxxx`           |
| `TICKET_PUBLIC_KEY` | online アカウント（Discord連携）のチケット署名検証に使う Ed25519 公開鍵（raw 32byte の base64．カンマ区切りで複数指定可＝鍵ローテーション用）．未設定・不正な場合はアカウント機能が無効になり，全接続がゲスト扱いになります | `xxxx`           |
| `TICKET_AUDIENCE`   | チケットの `aud`（自ホスト名）と一致するか検証します．他サーバー向けに発行されたチケットの流用を防ぎます | `tetlabo-canary.duckdns.org` |
